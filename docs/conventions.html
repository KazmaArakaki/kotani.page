CONVENTIONS

開発規約

1ページのサイトに、何年も手を入れずに済む状態を保つための約束ごと。 迷ったら「依存を増やさない」ほうを選ぶ。

構成

  • 新サイトは main ブランチで管理する。同じリポジトリの master は旧サイト（PHP 版）のソースで、参照用に残している。master には変更を加えない。
  • ビルド工程を持たない。public/ に置いたファイルが、そのまま配信される。
  • パッケージマネージャーは pnpm を使う（package.json の packageManager で版を固定）。依存は wrangler だけにする。CSS フレームワークや JavaScript ライブラリをサイトに入れない。
  • Node.js は、その時点の LTS を使う。dev container の Node feature は "version": "lts" にしてあり、コンテナを作り直すと最新の LTS が入る。
  • pnpm は依存パッケージのビルドスクリプトを既定で止める。wrangler が使う esbuild と workerd だけは pnpm-workspace.yaml の allowBuilds で許可している。許可はパッケージ名単位なので、wrangler を更新してもやり直す必要はない。
  • Worker のスクリプト（main）は、静的ファイルでどうしても返せないものが出てきたときにだけ足す。
  • 秘密情報は .dev.vars（Wrangler のローカル用）か .env に置く。どちらも .gitignore で除外している。共有したい雛形は .example を付けた名前でコミットする。
  • .bin/ はホストからコンテナ内のツールを呼ぶラッパー置き場。開発環境の一部としてコミットする。

ファイルの書き方

  • CSS と JavaScript は、旧サイトと同じく HTML の中に直接書く。
  • 色、フォント、余白は UI の基本方針の値を使う。新しい色を足さない。
  • 画像を差し替えるときは、ファイル名に日付を入れた新しいファイルを置く（例：cover.20211027.jpg）。同じ名前で上書きすると、ブラウザや CDN のキャッシュに古い画像が残るため。

ページを更新したら

  1. pnpm dev で手元の表示を確かめる
  2. sitemap.xml の <lastmod> を今日の日付にする
  3. 診療時間や住所を変えたときは、本文と構造化データ（JSON-LD）の両方を直す
  4. pnpm run deploy で公開する

ドキュメント

  • 新しいページは、近い既存ページを複製して作る。<head> とサイドバーの読み込みを揃えるため。
  • ページを足したら docs/sidebar.js の groups に追記する。
  • docs/ui/pages/ の中で index.html 以外の HTML（例：404/404.html）は成果物そのものなので、サイドバーを入れない。
